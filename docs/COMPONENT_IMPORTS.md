# Component Imports

How to import a Wasm component into a FastEdge JavaScript or TypeScript application and call its functions like a JS module.

## What a Component Is

A Wasm component is a compiled module with a typed interface described in WIT (the WebAssembly Interface Types language). Components can be built from Rust, Go, C/C++, Python and other languages. `fastedge-build` composes a component into the application's Wasm output, so the result is a single binary.

Use a component when:

- A library or existing code you need is written in another language.
- A hot path needs native speed.

For anything JS already does well, plain JS is simpler.

## Quick Start

This example uses the `example:image/thumbnail` interface from the `component-imports` example. It has four parts: the WIT interface, the build config, the application code and the generated type declarations.

### 1. The WIT Interface

The component exports this interface. The file is `thumbnail.wit`:

```wit
package example:image;

interface thumbnail {
  enum format { jpeg, png }

  record size { width: u32, height: u32 }

  record options {
    /// Thumbnails are never wider than this; smaller images keep their size
    max-width: u32,
    format: format,
  }

  /// Reads only the image header, so it is cheap: call it before `resize` to reject
  /// images too large to decode within the request's time and memory limits.
  dimensions: func(image: list<u8>) -> result<size, string>;

  /// Decodes a JPEG or PNG, scales it down keeping its aspect ratio, and encodes it.
  resize: func(image: list<u8>, options: options) -> result<list<u8>, string>;
}

world thumbnail-component {
  export thumbnail;
}
```

### 2. Build Configuration

Map the interface to the component file with the `components` field in `.fastedge/build-config.js`:

```js
export const config = {
  type: 'http',
  tsConfigPath: './tsconfig.json',
  entryPoint: './src/index.ts',
  wasmOutput: './dist/component-imports.wasm',
  // WIT interface the app imports → component that exports it
  components: {
    'example:image/thumbnail': './thumbnail.wasm',
  },
};
```

The same build from the command line:

```sh
fastedge-build -i src/index.ts -o dist/component-imports.wasm -t tsconfig.json \
  --component example:image/thumbnail=./thumbnail.wasm
```

| Setting                           | Form                               | Description                                                                     |
| --------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------- |
| `components` (build config field) | `Record<string, string>`, optional | Map of WIT interface name to component path, relative to the working directory. |
| `--component` (CLI flag)          | `<interface>=<path>`, repeatable   | Same mapping; the first `=` separates the interface name from the path.         |

See [BUILD_CLI.md](BUILD_CLI.md) for the other build options.

### 3. Application Code

Import the functions by interface name and call them:

```ts
import { dimensions, resize } from 'example:image/thumbnail';

// Decoding cost grows with the pixel count: reject large images before decoding
const MAX_PIXELS = 500_000;

async function handle(request: Request): Promise<Response> {
  const bytes = new Uint8Array(await request.arrayBuffer());
  try {
    const { width, height } = dimensions(bytes);
    if (width * height > MAX_PIXELS) {
      return new Response(`${width}x${height} is over the ${MAX_PIXELS}-pixel limit`, {
        status: 413,
      });
    }
    const thumbnail = resize(bytes, { maxWidth: 320, format: 'jpeg' });
    return new Response(thumbnail, { headers: { 'content-type': 'image/jpeg' } });
  } catch (error) {
    // A WIT `result` error is thrown, with the component's message in `payload`
    return new Response(`Cannot read image: ${(error as { payload: string }).payload}`, {
      status: 415,
    });
  }
}

addEventListener('fetch', (event: FetchEvent) => event.respondWith(handle(event.request)));
```

### 4. Generated Type Declarations

`fastedge-build` reads each interface from its component and writes TypeScript declarations to `fastedge-components.d.ts` before type-checking, so a call with the wrong types fails the build. In the example the file is `src/fastedge-components.d.ts`. It begins with this header and contains one `declare module` block per imported interface:

```ts
// Generated by fastedge-build from the configured components. Do not edit.

declare module 'example:image/thumbnail' {
  // …types and functions for the interface
}
```

The generated `fastedge-components.d.ts` is the authoritative description of a given component's types.

## Calling a Component

- Functions are imported by interface name, like a JS module: `import { resize } from 'example:image/thumbnail'`.
- The call is synchronous and returns the result directly. There is no `await`.
- Arguments and results are copied between the application and the component on every call. A large `Uint8Array` passed to a component is held in both memories while the call runs.

## WIT to JS Types

| WIT                                  | JS / TypeScript                                                            |
| ------------------------------------ | -------------------------------------------------------------------------- |
| `bool`                               | `boolean`                                                                  |
| integers up to 32 bits, `f32`, `f64` | `number`                                                                   |
| `u64` `s64`                          | `bigint`                                                                   |
| `char`, `string`                     | `string`                                                                   |
| `list<u8>`                           | `Uint8Array`                                                               |
| `list<f64>`                          | `Float64Array` (other number lists use the matching typed array)           |
| `list<string>`                       | `string[]`                                                                 |
| `record`                             | object; kebab-case field names become camelCase (`max-width` → `maxWidth`) |
| `enum`                               | string union (`'jpeg' \| 'png'`)                                           |
| `option<T>`                          | `T \| undefined`                                                           |
| `result<T, E>`                       | returns `T`; an error is thrown with the `E` value in `error.payload`      |
| `resource`                           | class                                                                      |

The generated `fastedge-components.d.ts` is the authoritative description of a given component's types.

## Errors

A WIT `result<T, E>` returns `T` on success. On error it throws an `Error` whose `payload` property holds the `E` value. For `result<size, string>`, `payload` is the error message string:

```ts
import { dimensions } from 'example:image/thumbnail';

function handle(bytes: Uint8Array): Response {
  try {
    const { width, height } = dimensions(bytes);
    return new Response(`${width}x${height}`);
  } catch (error) {
    // A WIT `result` error is thrown, with the component's message in `payload`
    return new Response(`Cannot read image: ${(error as { payload: string }).payload}`, {
      status: 415,
    });
  }
}

async function respond(request: Request): Promise<Response> {
  return handle(new Uint8Array(await request.arrayBuffer()));
}

addEventListener('fetch', (event: FetchEvent) => event.respondWith(respond(event.request)));
```

## Resources

A WIT `resource` becomes a JS class: its `constructor` becomes the class constructor, its methods become instance methods, and `static` functions become static methods. The generated class implements `Disposable`.

This WIT interface defines an `accumulator` resource:

```wit
package acme:calc;

interface memory {
  resource accumulator {
    constructor(start: f64);
    add: func(value: f64);
    total: func() -> f64;
    merge: static func(a: borrow<accumulator>, b: borrow<accumulator>) -> accumulator;
  }
}

world calculator {
  export memory;
}
```

With a component that exports `acme:calc/memory` configured as `'acme:calc/memory': './calculator.wasm'`, the application uses it as a class:

```ts
import { Accumulator } from 'acme:calc/memory';

function handle(url: URL): Response {
  const acc = new Accumulator(0);
  for (const v of url.searchParams.getAll('v')) acc.add(Number(v));
  const merged = Accumulator.merge(acc, new Accumulator(10));
  return new Response(`${acc.total()} ${merged.total()}`);
}

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(handle(new URL(event.request.url)));
});
```

## What a Component May Import

After linking, a component may import only:

- `wasi:*@0.2.x` interfaces
- `gcore:*` interfaces

Any other import fails the build with `Components import interfaces FastEdge does not provide: <names>`.

A component can make outgoing HTTP requests through `wasi:http`. These requests go through FastEdge like the application's own `fetch()`, and the same rules apply. For example, requests to private hosts are refused.

Outgoing HTTP, clocks, random and stdio are the WASI interfaces used by the SDK's tested components. Do not assume that every allowed WASI interface works at runtime.

## Several Components

One build can import interfaces from several component files, and several interfaces from one file. List each interface in `components`:

```js
export const config = {
  type: 'http',
  tsConfigPath: './tsconfig.json',
  entryPoint: './src/index.ts',
  wasmOutput: './dist/app.wasm',
  components: {
    'acme:calc/arith': './calculator.wasm',
    'acme:calc/format': './calculator.wasm',
    'example:image/thumbnail': './thumbnail.wasm',
  },
};
```

On the command line, repeat `--component`:

```sh
fastedge-build -i src/index.ts -o dist/app.wasm -t tsconfig.json \
  --component acme:calc/arith=./calculator.wasm \
  --component acme:calc/format=./calculator.wasm \
  --component example:image/thumbnail=./thumbnail.wasm
```

Two component files that export the same interface cannot be used in one build; see [Known Limitations](#known-limitations).

## Time and Memory Limits

Every request runs a fresh instance, so the work a component does is paid on every request. A request has a time and memory budget; on the free plan, 100 ms and 52 MB.

In the image example, decoding is the costly step, and its cost grows with the number of pixels. Measured on the edge:

| Image                     | Decode      | Whole component call | Memory |
| ------------------------- | ----------- | -------------------- | ------ |
| 612×640 JPEG (`kev.jpeg`) | ~10 ms      | ~20–30 ms            | 3 MB   |
| 1200×900 JPEG             | ~45–60 ms   | over 60 ms           | 9 MB   |
| 4000×3000 JPEG (12 MP)    | ~530–690 ms | over 700 ms          | 71 MB  |

Check sizes before expensive work. The example calls `dimensions()`, which reads only the image header, and rejects anything over `MAX_PIXELS` (0.5 MP) before calling `resize()`. Raise the limit only on a plan with a larger budget.

Progressive JPEGs decode about 3× slower than baseline ones; save images as baseline.

The component copies the image into its own memory for each call, so the bytes are held twice while it runs. That is small next to the decoded pixels (3 bytes per pixel for a JPEG).

## Writing a Component

Any language that builds Wasm components can implement the interface, for example Rust, Go (TinyGo), C/C++ (`wit-bindgen`) or Python (`componentize-py`). The component may only import what FastEdge provides; see [What a Component May Import](#what-a-component-may-import).

The `component-imports` example uses Rust with `wit-bindgen` and the `wasm32-wasip2` target.

`Cargo.toml` builds the crate as a dynamic library:

```toml
[lib]
crate-type = ["cdylib"]
```

Add `wit-bindgen` and any library the component needs as dependencies. Enable only the dependency features you use, to keep the component binary small.

`wit/thumbnail.wit` is the interface shown in [Quick Start](#quick-start), and `src/lib.rs` implements it:

```rust
// Image thumbnails for the component-imports example: exports example:image/thumbnail
// (see wit/thumbnail.wit) using the `image` crate.
wit_bindgen::generate!({ world: "thumbnail-component" });

use std::io::Cursor;

use exports::example::image::thumbnail::{Format, Guest, Options, Size};
use image::{ImageFormat, ImageReader};

struct Thumbnail;

impl Guest for Thumbnail {
    fn dimensions(image: Vec<u8>) -> Result<Size, String> {
        let (width, height) = ImageReader::new(Cursor::new(image))
            .with_guessed_format()
            .map_err(|e| e.to_string())?
            .into_dimensions()
            .map_err(|e| e.to_string())?;
        Ok(Size { width, height })
    }

    fn resize(image: Vec<u8>, options: Options) -> Result<Vec<u8>, String> {
        let img = image::load_from_memory(&image).map_err(|e| e.to_string())?;
        // `thumbnail` is a fast downscale; `min` stops small images being enlarged
        let thumb = img.thumbnail(options.max_width.min(img.width()), u32::MAX);
        let mut out = Cursor::new(Vec::new());
        match options.format {
            // JPEG has no alpha channel
            Format::Jpeg => thumb.to_rgb8().write_to(&mut out, ImageFormat::Jpeg),
            Format::Png => thumb.write_to(&mut out, ImageFormat::Png),
        }
        .map_err(|e| e.to_string())?;
        Ok(out.into_inner())
    }
}

export!(Thumbnail);
```

To rebuild the example's component, install the `wasm32-wasip2` target and run the example's build script:

```sh
rustup target add wasm32-wasip2
npm run build:component
```

Commit the built `.wasm` file, so that building the application needs no Rust toolchain.

## Build Errors

| Error                                                                                                                            | Cause                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `--component expects <interface>=<path>, got "<value>"`                                                                          | A `--component` value has no `=`, or nothing before it.                                               |
| `Invalid component interface name: <names> (expected "namespace:package/interface")`                                             | The name is not `namespace:package/interface`, optionally followed by `@version`.                     |
| `Component "<path>" is not a readable file`                                                                                      | The path does not exist or cannot be read.                                                            |
| `"<path>" is not a Wasm component`                                                                                               | The file is not a Wasm component.                                                                     |
| `no component exports <interface>`                                                                                               | No given component file exports the interface.                                                        |
| `<interface> is exported by more than one component: <paths>. Components that export the same interface cannot be used together` | More than one component file exports the interface, even if `components` maps it to only one of them. |
| `Components import interfaces FastEdge does not provide: <names>`                                                                | After linking, an interface other than `wasi:*@0.2.x` or `gcore:*` remains imported.                  |

## Known Limitations

- A component whose exported interface uses types from another interface must also export that interface. Otherwise the build fails with the "does not provide" error for it.
- Components are linked in after the application is pre-initialized, so a component's own state is not pre-initialized. The first call in each request pays the component's start-up work.
- Two component files that export the same interface the application imports cannot be used in one build, even when `components` maps that interface to only one of them. The build fails with the "exported by more than one component" error.
