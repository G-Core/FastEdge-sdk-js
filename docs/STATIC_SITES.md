# Static Sites

Serve static files from a FastEdge WebAssembly binary with no file-system access at runtime.

## How Embedding Works

The FastEdge runtime runs inside a WebAssembly sandbox with no access to a host file system. Static files must be embedded directly into the `.wasm` binary at compile time.

The build pipeline uses [Wizer](https://github.com/bytecodealliance/wizer) for pre-initialization. Wizer executes all top-level JavaScript in your entry point before taking a memory snapshot. When `createStaticServer` is called at the top level, it reads every file listed in the asset manifest with `readFileSync` from `fastedge::fs` and holds the bytes in WebAssembly linear memory. Wizer then snapshots that memory state and writes it into the final binary. At runtime, assets are served directly from memory.

This means:

- `createStaticServer` **must** be called at module top level, not inside a function or event handler.
- The asset manifest must exist before the entry point is compiled.
- Any file not included in the manifest at build time cannot be served at runtime.

## Quick Start

### Step 1: Scaffold the project

```sh
npx fastedge-init
```

Select the static site type. `fastedge-init` prompts for:

| Prompt                                                | Default                        | Notes                                                            |
| ----------------------------------------------------- | ------------------------------ | ---------------------------------------------------------------- |
| Path to your output file                              | `.fastedge/dist/fastedge.wasm` | Must end in `.wasm`                                              |
| Path to your public directory                         | `./build`                      | Must be an existing, non-empty directory                         |
| Is your site a single page application?               | No                             | Answer yes to be prompted for an SPA entrypoint                  |
| Path to your SPA entrypoint (only when answering yes) | `./index.html`                 | Must exist in the public directory, otherwise a warning is shown |

The SPA entrypoint must be a file inside the public directory, both as typed and after symlinks are resolved. If it is not, a warning is shown and no SPA entrypoint is set.

It writes `.fastedge/static-index.js` (the entry point), `.fastedge/build-config.js` (build and server config), and a `package.json` and `jsconfig.json` in `.fastedge/`.

The generated entry point:

```js
/*
 * Generated by @gcoredev/FastEdge-sdk-js fastedge-init
 */

import { createStaticServer } from "@gcoredev/fastedge-sdk-js";
import { staticAssetManifest } from "./build/static-asset-manifest.js";
import { serverConfig } from "./build-config.js";

const staticServer = createStaticServer(staticAssetManifest, serverConfig);

async function handleRequest(event) {
  const response = await staticServer.serveRequest(event.request);
  if (response != null) {
    return response;
  }

  return new Response("Not found", { status: 404 });
}

addEventListener("fetch", (event) => event.respondWith(handleRequest(event)));
```

### Step 2: Build

```sh
npx fastedge-build --config .fastedge/build-config.js
```

With `type: "static"`, the asset manifest is generated as part of the build pipeline. See [Build Config](#build-config).

### Without fastedge-init

Generate the manifest manually, write the entry point yourself, and build with explicit paths.

```sh
npx fastedge-assets ./public ./src/asset-manifest.ts
```

This scans `./public` and writes a manifest module mapping each file's URL path to its metadata. Do not edit the manifest by hand.

```ts
/// <reference types="@gcoredev/fastedge-sdk-js" />
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Must be at top level — Wizer snapshots this call
const server = createStaticServer(staticAssetManifest, {
  autoIndex:    ['index.html'],
  autoExt:      ['.html'],
  notFoundPage: '/404.html',
});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

```sh
npx fastedge-build --input ./src/index.ts --output ./dist/app.wasm
```

## Build Config

`fastedge-init` writes `.fastedge/build-config.js` containing both the build config (`config`) and the server config (`serverConfig`). The values are written with `JSON.stringify`, so keys are double-quoted. The generated entry point imports `serverConfig` from this file, so the file must keep exporting it, and the manifest must stay at the default path `.fastedge/build/static-asset-manifest.js`.

```js
// .fastedge/build-config.js
const config = {
  "type": "static",
  "entryPoint": ".fastedge/static-index.js",
  "ignoreDotFiles": true,
  "ignorePaths": [
    "/drafts"
  ],
  "ignoreWellKnown": false,
  "tsConfigPath": "./tsconfig.json",
  "wasmOutput": ".fastedge/dist/fastedge.wasm",
  "publicDir": "./public"
};

const serverConfig = {
  "type": "static",
  "extendedCache": [],
  "publicDirPrefix": "",
  "compression": [],
  "notFoundPage": "/404.html",
  "autoExt": [],
  "autoIndex": [
    "index.html",
    "index.htm"
  ],
  "spaEntrypoint": null
};

export { config, serverConfig };
```

`fastedge-init` writes `ignorePaths: ["./node_modules"]` by default. The example above replaces it with `"/drafts"`.

### Static-Specific BuildConfig Fields

The following fields apply when `type` is `'static'`. All other `BuildConfig` fields are documented in [BUILD_CLI.md](BUILD_CLI.md).

| Field               | Type                           | Required | Description                                                                                            |
| ------------------- | ------------------------------ | -------- | ------------------------------------------------------------------------------------------------------ |
| `publicDir`         | `string`                       | No       | Directory to scan for static files to embed; defaults to the current directory                         |
| `assetManifestPath` | `string`                       | No       | Output path for the generated manifest module; defaults to `.fastedge/build/static-asset-manifest.js`  |
| `contentTypes`      | `Array<ContentTypeDefinition>` | No       | Custom content-type definitions                                                                        |
| `ignoreDotFiles`    | `boolean`                      | No       | When `true` (default), excludes files and directories whose names begin with `.`, except `.well-known` |
| `ignorePaths`       | `string[]`                     | No       | Paths to exclude, relative to `publicDir` and matched exactly (e.g. `'/drafts'`)                       |
| `ignoreWellKnown`   | `boolean`                      | No       | When `true`, excludes the `.well-known/` directory; default `false`                                    |

`fastedge-build` does not check `publicDir` beforehand. A missing directory fails the build, and an empty directory produces an empty manifest.

If `assetManifestPath` does not end in `.js`, `.ts`, `.cjs`, or `.mjs`, a `.js` extension is appended. If the resulting path exists and is not a file, a warning is shown and the default path is used.

#### Symlinks

Symlinks in `publicDir` are followed only when they resolve to a regular file inside `publicDir`. Links to directories, links pointing outside `publicDir`, and broken links are skipped with a warning.

## createStaticServer

```typescript
function createStaticServer(
  staticAssetManifest: StaticAssetManifest,
  serverConfig: Partial<ServerConfig>,
): StaticServer
```

Creates a static server that serves assets from an in-memory cache built from `staticAssetManifest`.

**Parameters:**

| Parameter             | Type                    | Description                                                        |
| --------------------- | ----------------------- | ------------------------------------------------------------------ |
| `staticAssetManifest` | `StaticAssetManifest`   | Manifest generated by `fastedge-assets` or the `static` build type |
| `serverConfig`        | `Partial<ServerConfig>` | Server behavior options; all fields are optional                   |

**Returns:** `StaticServer`

**Critical constraint:** This function must be called at module top level. It reads asset files with `readFileSync` from `fastedge::fs`, which only works during Wizer pre-initialization. Calling it inside a request handler throws at request time. See [Wizer Constraint](#wizer-constraint).

### Import

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
```

### ServerConfig Fields

```typescript
interface ServerConfig extends Record<string, unknown> {
  extendedCache:   Array<string | RegExp>;
  publicDirPrefix: string;
  routePrefix?:    string;
  compression:     string[];
  notFoundPage:    string | null;
  autoExt:         string[];
  autoIndex:       string[];
  spaEntrypoint:   string | null;
}
```

All fields are optional when passed to `createStaticServer`. Pass only the fields you need.

| Field             | Type                      | Default | Description                                                                                 |
| ----------------- | ------------------------- | ------- | ------------------------------------------------------------------------------------------- |
| `publicDirPrefix` | `string`                  | `''`    | Prefix prepended to the request path (after `routePrefix` is removed) to form the asset key |
| `routePrefix`     | `string`                  | `'/'`   | URL prefix removed from the request path before the asset lookup; `'/'` applies no prefix   |
| `extendedCache`   | `Array<string \| RegExp>` | `[]`    | Paths or patterns that receive `Cache-Control: max-age=31536000`                            |
| `compression`     | `string[]`                | `[]`    | Accepted but not implemented; has no effect on responses                                    |
| `notFoundPage`    | `string \| null`          | `'/'`   | Asset key served with status 404 when no asset matches; HTML-accepting requests only        |
| `autoExt`         | `string[]`                | `[]`    | Suffixes appended to the path when no exact match is found (e.g. `['.html']`)               |
| `autoIndex`       | `string[]`                | `[]`    | Index file names tried for the path treated as a directory (e.g. `['index.html']`)          |
| `spaEntrypoint`   | `string \| null`          | `'/'`   | Asset key served for unmatched routes (SPA fallback); HTML-accepting requests only          |

The defaults are the values after the server config is normalized. An unset `notFoundPage` or `spaEntrypoint` (or one set to `null`) becomes `'/'`, which matches no asset, so the feature is effectively off.

The server config written by `fastedge-init` sets `notFoundPage` to `'/404.html'` and `autoIndex` to `['index.html', 'index.htm']`. It sets `spaEntrypoint` to the asset key of the SPA entrypoint you entered (for example `'/index.html'`), or `null`.

#### compression

`compression` is accepted in the server config but is not implemented. Responses never get a `Content-Encoding` header, and no content-encoding negotiation takes place. Assets are always served as embedded.

#### routePrefix

Use `routePrefix` when mounting a static server under a URL subpath. The prefix is removed from the request path before the server looks up an asset key.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Assets have keys like '/logo.png', '/style.css'
// Requests arrive as '/static/logo.png', '/static/style.css'
const server = createStaticServer(staticAssetManifest, { routePrefix: '/static' });

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

#### publicDirPrefix

Use `publicDirPrefix` when asset keys in the manifest include a directory prefix that request paths do not. The prefix is prepended to the request path to form the asset key. When `routePrefix` is unset, the leading `/` of the request path is removed before the prefix is prepended, so end `publicDirPrefix` with `/`.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Assets have keys like '/public/logo.png'
// Requests arrive as '/logo.png'
const server = createStaticServer(staticAssetManifest, { publicDirPrefix: '/public/' });

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

#### extendedCache

Each entry is matched against the request pathname:

- A `RegExp` entry matches when `test(pathname)` is true.
- A string ending in `/` matches as a path prefix, so `'/assets/'` matches every path under `/assets/` and `'/'` matches every path.
- Any other string must equal the pathname exactly.

A string of the form `regex:/pattern/flags` is converted to a regular expression. Use this form in a config file that is serialized with `JSON.stringify` (such as `.fastedge/build-config.js`). An invalid pattern is dropped with a warning.

Matching responses carry `Cache-Control: max-age=31536000`.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

const server = createStaticServer(staticAssetManifest, {
  extendedCache: [
    '/logo.png',
    '/assets/',
    /\.woff2$/i,
  ],
});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

#### autoExt and autoIndex

When a path does not end in `/`, the server first looks for an asset at the exact path, then tries each `autoExt` suffix appended to it. If `autoIndex` is configured, the server then treats the path as a directory and tries each index file name inside it.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Request: /about   → tries /about, then /about.html, then /about/index.html
// Request: /docs/   → tries /docs/index.html
const server = createStaticServer(staticAssetManifest, {
  autoExt:   ['.html'],
  autoIndex: ['index.html'],
});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

#### notFoundPage and spaEntrypoint

Both `notFoundPage` and `spaEntrypoint` are only served for requests that include `text/html`, `*/*`, or `*` in their `Accept` header. Other requests (for example API calls and asset fetches) that match no asset resolve to `void`, regardless of these settings.

The values are raw asset keys. `routePrefix` and `publicDirPrefix` are not applied to them.

`spaEntrypoint` is checked first. If it resolves to an asset, it is returned with status 200 and `Cache-Control: no-store`, and `notFoundPage` is never reached. If not, `notFoundPage` is checked and returned with status 404 and `Cache-Control: no-store`.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Client-side routing: all unmatched HTML requests get /index.html
const spaServer = createStaticServer(staticAssetManifest, {
  spaEntrypoint: '/index.html',
});

// Static site with explicit 404 page
const siteServer = createStaticServer(staticAssetManifest, {
  notFoundPage: '/404.html',
});

addEventListener('fetch', (event: FetchEvent) => {
  const { pathname } = new URL(event.request.url);
  const server = pathname.startsWith('/app/') ? spaServer : siteServer;
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

## StaticServer Methods

```typescript
interface StaticServer {
  serveRequest(request: Request): Promise<void | Response>;
  readFileString(path: string):   Promise<string>;
}
```

### serveRequest

```typescript
serveRequest(request: Request): Promise<void | Response>
```

Looks up the asset matching the pathname of `request.url` and returns a `Response`.

Only `GET` and `HEAD` requests are processed. All other methods resolve to `void`.

Response headers:

| Header          | When it is set                                                                    |
| --------------- | --------------------------------------------------------------------------------- |
| `Content-Type`  | Always, from the asset's content type                                             |
| `ETag`          | Always, from the asset's content hash                                             |
| `Last-Modified` | When the asset's modification time is known; omitted when it is unknown (0)       |
| `Cache-Control` | `max-age=31536000` for `extendedCache` matches; `no-store` for fallback responses |

The fallback responses are the `spaEntrypoint` and `notFoundPage` responses. `Content-Encoding` is never set. See [compression](#compression).

Conditional requests are handled with `If-None-Match` and `If-Modified-Since`. When the precondition shows the client copy is current, the server returns a `304` response containing only the `Content-Location`, `ETag`, `Vary`, `Cache-Control`, and `Expires` headers that were set on the response.

Returns `void` (resolves to `undefined`) when no asset matches and no applicable `notFoundPage` or `spaEntrypoint` is configured. The caller must provide a fallback response in that case.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

const server = createStaticServer(staticAssetManifest, {});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

### readFileString

```typescript
readFileString(path: string): Promise<string>
```

Returns the text content of the embedded asset at `path`. The path is resolved with the same rules as request paths (`routePrefix`, `publicDirPrefix`, `autoExt`, `autoIndex`). The asset must have been classified as a text type (`isText: true`) in the manifest at build time; otherwise the call throws `Can't getText() for non-text content`. Throws an `Error` with the message `Asset not found` if no asset is found at the given path. Use this to read embedded HTML templates or other text files for further processing at runtime.

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

const server = createStaticServer(staticAssetManifest, {});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    (async () => {
      const html = await server.readFileString('/template.html');
      return new Response(html, { headers: { 'Content-Type': 'text/html' } });
    })(),
  );
});
```

## Wizer Constraint

Wizer pre-initializes the binary by running all top-level module code before snapshotting memory. `createStaticServer` reads asset files with `readFileSync` from `fastedge::fs`, which only works during Wizer pre-initialization. It must be called at the **module top level**. Calling it inside a request handler throws at request time.

The `fastedge::fs` module declares:

```typescript
declare module 'fastedge::fs' {
  export function readFileSync(path: string): Uint8Array;
}
```

`readFileSync` reads a file synchronously and can only be invoked during build-time initialization.

**Correct:**

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Top-level: runs during Wizer pre-initialization
const server = createStaticServer(staticAssetManifest, {});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(
    server.serveRequest(event.request).then(
      (response) => response ?? new Response('Not found', { status: 404 }),
    ),
  );
});
```

**Incorrect — throws at request time:**

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './asset-manifest.js';

// Do not do this
addEventListener('fetch', (event: FetchEvent) => {
  const server = createStaticServer(staticAssetManifest, {}); // inside handler
  event.respondWith(server.serveRequest(event.request));
});
```

## Multiple Manifests

A single entry point can use multiple static servers, each built from a separate manifest. This is useful when different asset groups need different server configurations (e.g., separate route prefixes or cache policies).

```sh
npx fastedge-assets ./images    src/images-manifest.ts
npx fastedge-assets ./styles    src/styles-manifest.ts
npx fastedge-assets ./templates src/templates-manifest.ts
npx fastedge-build -i src/index.ts -o dist/app.wasm -t tsconfig.json
```

```ts
/// <reference types="@gcoredev/fastedge-sdk-js" />
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest as imagesManifest }    from './images-manifest.js';
import { staticAssetManifest as stylesManifest }    from './styles-manifest.js';
import { staticAssetManifest as templatesManifest } from './templates-manifest.js';

// All three must be at top level
const imageServer    = createStaticServer(imagesManifest,    { routePrefix: '/images' });
const styleServer    = createStaticServer(stylesManifest,    { routePrefix: '/styles' });
const templateServer = createStaticServer(templatesManifest, {});

addEventListener('fetch', (event: FetchEvent) => {
  const { pathname } = new URL(event.request.url);
  let server = templateServer;
  if (pathname.startsWith('/images/')) {
    server = imageServer;
  } else if (pathname.startsWith('/styles/')) {
    server = styleServer;
  }
  event.respondWith(
    server
      .serveRequest(event.request)
      .then((r) => r ?? new Response('Not found', { status: 404 })),
  );
});
```

## v1 to v2 Migration

Version 2.x replaced the two-step `createStaticAssetsCache` + `getStaticServer` pattern with a single `createStaticServer` call.

**Version 1.x:**

```ts
import { getStaticServer, createStaticAssetsCache } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './build/static-server-manifest.js';
import { serverConfig }        from './build-config.js';

const staticAssets = createStaticAssetsCache(staticAssetManifest);
const staticServer = getStaticServer(serverConfig, staticAssets);

async function handleRequest(event) {
  const response = await staticServer.serveRequest(event.request);
  if (response != null) {
    return response;
  }
  return new Response('Not found', { status: 404 });
}

addEventListener('fetch', (event) => event.respondWith(handleRequest(event)));
```

**Version 2.x:**

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { staticAssetManifest } from './build/static-asset-manifest.js';
import { serverConfig }        from './build-config.js';

const staticServer = createStaticServer(staticAssetManifest, serverConfig);

async function handleRequest(event) {
  const response = await staticServer.serveRequest(event.request);
  if (response != null) {
    return response;
  }
  return new Response('Not found', { status: 404 });
}

addEventListener('fetch', (event) => event.respondWith(handleRequest(event)));
```

**What changed:**

| Area                | v1.x                                          | v2.x                                       |
| ------------------- | --------------------------------------------- | ------------------------------------------ |
| API                 | `createStaticAssetsCache` + `getStaticServer` | `createStaticServer`                       |
| Multiple manifests  | Not supported                                 | Supported — one server per manifest        |
| Read file as string | Not available                                 | `server.readFileString(path)`              |
| Manifest file name  | `static-server-manifest.js`                   | `static-asset-manifest.js` (by convention) |

To regenerate the entry point for an existing project, re-run `npx fastedge-init`. It prompts again for the project settings and asks before overwriting the existing `build-config.js`. It does not update the build config silently.
